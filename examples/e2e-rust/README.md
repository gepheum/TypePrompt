# TypePrompt Rust End-to-End Example

An SRE Incident Commander and automated triage assistant built with Rust, TypePrompt, and the Google Gemini API (`generateContent`), demonstrating **end-to-end typed tool calling** and **structured JSON output**.

---

## Prerequisites

- Rust 1.75 or higher (with Cargo)
- Node.js 18 or higher (for `npx @typeprompt/cli`)
- A Google Gemini API key (`GEMINI_API_KEY`) from [Google AI Studio](https://aistudio.google.com/)

---

## Project Structure

```
.
├── Cargo.toml                 # Rust package configuration & dependencies
├── typeprompt.yaml            # TypePrompt configuration
├── prompts/
│   ├── meta.tp               # Metadata declaration (model, temperature)
│   ├── getServiceMetrics.tp  # Tool definition (Input & Output schema)
│   └── TriageIncident.tp     # Prompt template registering getServiceMetrics tool
└── src/
    ├── gen/
    │   └── prompts.rs         # Auto-generated by TypePrompt
    └── main.rs                # Application entry point & execute_prompt Gemini runner
```

---

## 1. Generate Code

To generate the typed prompt and tool code from your XML templates:

```bash
npx @typeprompt/cli gen
```

This generates `src/gen/prompts.rs` containing:
- `PROMPTS.render_triage_incident(...)` for rendering the prompt with typed arguments (`schema::triage_incident::Input`).
- `tool_executor::GetServiceMetrics` trait enforcing the `get_service_metrics` method signature.
- `schema::triage_incident::Output` and `schema::get_service_metrics::Output` typed Serde data structures.

---

## 2. Run the Application

Set your Gemini API key and run with Cargo:

```bash
export GEMINI_API_KEY="AIza..."
cargo run
```

You can also pass a custom service name and reported issue:

```bash
cargo run -- "payment-service" "Elevated checkout timeouts and downstream database connection pool exhaustion."
```

or:

```bash
cargo run -- "auth-api" "Spike in HTTP 500 errors and token verification latencies during morning login rush."
```

## How It Works

1. **Prompt Resolution**: `PROMPTS.render_triage_incident(...)` resolves template placeholders (`service`, `reported_issue`), sets JSON mode in generation configuration (`responseMimeType: "application/json"`), and binds tool definitions.
2. **Tool Invocation**: Gemini inspects the incident context and issues a `getServiceMetrics` function call to inspect CPU, memory, P99 latency, error rates, and replica counts.
3. **Typed Execution**: `prompt.execute_tools(...)` safely dispatches the call to `MetricsExecutor.get_service_metrics(input)` and formats the serialized `functionResponse` back to Gemini.
4. **Structured JSON Validation**: Gemini synthesizes the metrics into an actionable root-cause analysis, and `prompt.parse_response(&text)` validates and deserializes the response directly into the typed `schema::triage_incident::Output` struct.
